The Name Problem

Same data point. Same mission. But EPICS and TANGO can't even agree on what to call it — and behind the naming difference hides a deeper philosophical divide.

Slide 3 — "Same Data Point. Two Very Different Philosophies."

🔵 EPICS Side

Process Variable (PV)

Name it whatever you want. No rules. No database. No referee. Two PVs can share the same name on the same network. The team decides the conventions. Or doesn't.

temperature
my_temperature
TEST_temp_v2
// same network. no conflict detected.
⚡ Flexible — but watch your naming
🟠 TANGO Side

Attribute

Every value belongs to a Device. Every Device has a unique address. The database enforces uniqueness. No duplicates. Ever. By design.

DOMAIN / FAMILY / DEVICE
→ Attribute: temperature

LHC / Cryogenics / Valve01
→ temperature // unique. guaranteed.
✅ Structured — uniqueness enforced by contract

"In EPICS, naming is a convention. In TANGO, it's a contract. Two philosophies. Both valid. We'll go deeper in a future episode."

EPICS — How the Network Sends a Message

No polling. No asking. No "hey, are you there?" Just pure, elegant listening. EPICS uses a publish/subscribe model called Channel Access — upgraded in modern deployments to PV Access.

Slide 4 — "How EPICS Sends a Message."

Step 1 — Subscribe

Luke registers

"I want to know every time Reactor 4 temperature changes." He registers. Done.

Step 2 — Wait

The network listens

Always. Luke grabs a snack. The Emperor's network stands guard so he doesn't have to.

Step 3 — Receive

Instant update

The moment something changes — Luke gets the update. Instantly. No delay. No questions asked.

Channel Access → PV Access. Same idea. Full HD transmission. Backward compatible. The Empire upgraded its hologram codec.

TANGO — How the Network Sends a Message

TANGO didn't start with one protocol. It started with CORBA — structured, reliable, very Imperial — and evolved into something much more Force-sensitive: ZeroMQ.

Slide 5 — "How TANGO Sends a Message."

📜 CORBA — The Classic

"Send a messenger droid. Wait for it to come back. Ask: 'Hey, what's the current value?'"

Reliable. Structured. Very Imperial. A little slow. Works great — until the galaxy gets impatient.

Polling model
⚡ ZMQ — The Modern

"Don't ask. Just feel the change — the moment it happens. Like a direct Force connection."

Event-driven. Blazing fast. TANGO's glow-up moment. From messenger droid to Force lightning.

Event-driven model

EPICS — Darth Vader's Command Ship: The IOC

Meet the IOC — Input Output Controller. A software program running on a server. It commands every Process Variable under its watch. It exposes them to the network. Every. Single. One.

Slide 6 — "Darth Vader's Command Ship — The IOC."

📖 READ Door

Temperature too high? READ. The IOC reports it to the network. Accurate. Instant. Unwavering.

✏️ WRITE Door

Change a setpoint? WRITE. The IOC accepts the command. Applies it. Confirms it. The Empire obeys.

A PV enters through one door only — READ or WRITE. Not both simultaneously. That's not a bug. That's architecture by design.

Battle-tested in particle accelerators, fusion reactors, space telescopes. The IOC doesn't complain. It just works. 🏆

TANGO — The Device Server & the Secret Weapon

The Device Server is TANGO's IOC equivalent. Attributes in read. Attributes in write. Looks familiar so far, right? But then — TANGO pulls out something EPICS doesn't have natively.

Slide 7 — "The Device Server — and the Secret Weapon."

📖 Read Attribute

Same as EPICS. The Device Server exposes a value. The network reads it. Clean and simple.

✏️ Write Attribute

Same as EPICS. Send a new value. The Device Server accepts it. Business as usual.

🔴 Command

This is the secret weapon. One call. One action — or an entire chain of events across the galaxy. Like Order 66, but hopefully for science.

"A Command can be simple: 'Turn on.' One call. One action. Or a Command can be Order 66. One call. The galaxy changes in seconds."

That's the TANGO Command. One call. Potentially a LOT of consequences. Choose wisely.

What You Now Know, Padawan 🎓

Slide 9 — "What You Now Know, Padawan."

⚡ Same Droid, Different Badge. EPICS calls it PV. TANGO calls it Attribute. Same Droid under the hood — different name tag pinned to its chest.

📡 Two Network Philosophies. EPICS uses Channel Access — subscribe and receive. TANGO started with CORBA, evolved to ZMQ. Messenger droid → Force connection.

🧠 IOC vs. Device Server. EPICS runs IOCs — PVs in read OR write. TANGO runs Device Servers — plus the secret weapon you're about to memorize forever.

🔴 Commands Are TANGO's Superpower. Simple action — or Order 66. One call. Your choice. EPICS doesn't have this natively. That's not a flaw — that's a design philosophy.

🔵 EPICS — The American Story

Glossary

Every technical term used in this guide — with plain-English definitions and links back to where they appear.

PV — Process Variable
EPICS — data point name
A named measurement or control value in EPICS. Accessible either in read or in write. No uniqueness enforced by the system — naming conventions are the team's responsibility.
↑ See in guide — The Name Problem
Attribute
TANGO — data point name
The TANGO equivalent of an EPICS PV. Every Attribute belongs to a Device. Every Device has a unique address (DOMAIN/FAMILY/DEVICE). Uniqueness is enforced by the Tango Database — no duplicates, ever.
↑ See in guide — The Name Problem
Channel Access (CA)
EPICS — classic network protocol
The original EPICS communication protocol, in use since the late 1980s. Works on a publish-subscribe model: a client subscribes to a channel and receives updates automatically when a value changes.
↑ See in guide — EPICS Network
PV Access
EPICS — modern network protocol
The modern successor to Channel Access. Faster, more flexible, and better suited for complex data structures. Backward compatible. The Empire upgraded its hologram codec.
↑ See in guide — EPICS Network
CORBA
Common Object Request Broker Architecture — TANGO classic protocol
The middleware used by TANGO in its earlier versions. Works on a polling model: the client regularly asks the server for the current value. Reliable and structured — very Imperial. A little slow for real-time use cases.
↑ See in guide — TANGO Network
ZeroMQ / ZMQ
Zero Message Queue — TANGO modern protocol
The modern event-driven messaging library used by TANGO. The server pushes updates the moment a value changes. No polling. Pure reactivity — like a direct Force connection between sender and receiver.
↑ See in guide — TANGO Network
IOC
Input Output Controller — EPICS brain unit
The core software unit in EPICS. A program running on a server that exposes Process Variables to the network — either in read, or in write. Not both simultaneously. Battle-tested in accelerators, fusion reactors, space telescopes.
↑ See in guide — EPICS Brain
Device Server
TANGO brain unit — IOC equivalent
The core software unit in TANGO. Like an IOC, it exposes Attributes in read and write. But it adds Commands — reusable actions that can execute simple operations or trigger complex sequences.
↑ See in guide — TANGO Brain
Command
TANGO — secret weapon
TANGO's extra capability beyond what EPICS offers natively. A Command exposed by a Device Server can be a simple action ("Turn on") or trigger a complex sequence across the entire system. Like Order 66 — one call, many consequences.
↑ See in guide — TANGO Brain
Tango Database
TANGO — device registry
A central database that stores all Device addresses on a TANGO network. It enforces the uniqueness of DOMAIN/FAMILY/DEVICE addresses — guaranteeing that no two Devices share the same identifier on the network.
↑ See in guide — The Name Problem
Publish / Subscribe
Network communication model
A communication pattern where a client subscribes to a data source and receives automatic updates when the value changes — without having to ask repeatedly. Used by EPICS Channel Access and TANGO ZMQ events.
↑ See in guide — EPICS Network
Polling
Network communication model
A communication pattern where the client regularly asks the server: "What's the current value?" The server answers each time. Used by TANGO CORBA. Reliable but less reactive than event-driven approaches.
↑ See in guide — TANGO Network
